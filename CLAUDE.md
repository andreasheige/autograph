# Autograph — working notes

Architecture, data flow, vault layout, and the full command table live in
`README.md` and `docs/architecture.md`. Read those first — this file only covers
what they don't.

## Common commands

```bash
python3 -m pytest tests/ -q              # full suite, quiet (76 tests, ~1s)
python3 run_daily_backfill.py --days 7   # what the 08:00 launchd job runs
```

`pytest` resolves `src.*` from the repo root on its own — no `PYTHONPATH` needed.
Standalone scripts outside `tests/` do need `PYTHONPATH=.` unless they bootstrap
`sys.path` themselves (only `run_summary.py` and `run_desktop_capture_server.py` do).

## Running the pipeline has real side effects

`run_daily_backfill.py` is not a dry run, and there is no dry-run flag:

- One Ollama call per work unit, plus one per day overview. A heavy day is ~20
  calls; a 7-day window can be 70–80.
- If any note is created, `sync_agent.py` stages `**/*.md`, commits, and
  **pushes the vault to its git remote**.

To inspect date selection or work-unit counts without writing or pushing, build
units directly (`normalize_events` → `build_work_units`). `history_since` is
documented as cursor-free and is safe to call read-only.

## Invariants worth not breaking

- **Time and cost are estimates per whole session and day.** `src/core/usage.py`
  prices Claude's per-response `usage` at API list prices (a hand-kept table:
  update it when prices or models change; unknown models count as unpriced
  tokens). Claude repeats a response's usage on every line of a multi-block
  message, so `usage_since` keys on the message id. Active time counts only
  pauses of at most 15 minutes (`ACTIVE_GAP_THRESHOLD`). Neither is in the
  fingerprint, so like any renderer change they show up when a note regenerates.

- **The window is floored to midnight** (`daily_backfiller.py:183`). A rolling
  `now - days` instant leaves the oldest date half-inside the window, which
  truncates that day's note and makes its fingerprint drift on every run. Keep
  the floor.
- **Fingerprint state** (`~/.autograph/logs/daily_note_state.json`) is what makes
  reruns idempotent. Anything that changes unit selection — window width,
  `MAX_DAILY_WORK_UNITS` — invalidates it and regenerates the whole window once.
- **`*Generated by Autograph Agent*`** is the only thing protecting manual notes
  from being overwritten. `--replace-generated` deletes marked notes.
- **Strip ids parsed out of `git log --pretty=format`.** It separates *records*
  with a newline, so with the trailing `%x00` in `_commits_since` every id after
  the first arrives as `"\nsha"`. That newline lands inside the wikilink and
  splits it across three lines — a dead graph edge whose tell is an 11-character
  short id. It broke 59 links across five daily notes before the `.strip()`.
- **Renderer changes are invisible until a note regenerates.**
  `fingerprint_work_day` covers unit and commit content only, so changing
  `daily_note_renderer.py` does not invalidate state. Existing notes keep their
  old shape until `--replace-generated` runs for those dates. The same holds
  for `vocabulary.md` and wiki tags, except that `run_daily_note_retrofit.py`
  refreshes `tags`, frontmatter and **Related wiki** links in place, without
  Ollama. It reads everything back out of the note, so keep the renderer's
  section labels (`**Related project:**`, `**Agent source:**`, `**Models:**`)
  stable, or teach `retrofit_daily_note` the new ones.
- **A work unit's evidence is capped at `MAX_UNIT_EVIDENCE`, silently.**
  `WorkUnit.prompt()` stops appending events once the formatted evidence
  passes 6000 chars — it truncates to a chronological prefix, it does not
  sample. A single long-running session used to become one `WorkUnit` no
  matter how many hours it spanned, so a 12-hour, 1800-event session was
  cut down to whatever fit in its first ~40 minutes before reaching the
  synthesizer — everything after that was invisible to the LLM and never
  made it into the note, even though the events were retained. Grouping in
  `build_work_units` now runs unit_events through `_split_session_events`,
  which starts a new chunk at an idle gap over `SESSION_GAP_THRESHOLD` **or**
  once accumulated evidence would exceed `MAX_UNIT_EVIDENCE` — so a unit's
  own prompt fits without truncation instead of dropping everything past the
  cutoff. `_cap_units_per_day` then caps chunks per session
  (`MAX_SESSION_WORK_UNITS`) before ranking the day, so a single long session
  chunked into many candidates can't crowd out every other session that day
  under `MAX_DAILY_WORK_UNITS`.
- **Only Copilot and Claude session IDs identify a session.** Codex records carry
  `session_id` on `session_meta` alone and Pi on its `session` record alone, so
  every other record in those files falls back to `source_path.parent.name` —
  `04` for `~/.codex/sessions/2026/09/04/`, the cwd-encoded directory for Pi.
  All Codex sessions on one day therefore collapse into one work unit, and those
  sections get no `**Session:**` link. `_sections_for_units` gates on membership
  in the `session_metadata` map, which is keyed by real IDs read from the
  transcripts. Fixing the fallback would change work-unit grouping and so
  invalidate every fingerprint for those days.
- **Desktop captures make their own session note.** `claudedesktop` events
  carry an id like `<title-slug>-<6 hex>`, and the capture server writes the
  full note at `sessions/claudedesktop/<id>.md`. That is the path the daily
  note's **Session:** link points to, and `write_session_note` never
  overwrites an existing file, so the stub writer leaves it alone. The server
  speaks MCP over stdout: a stray `print` there corrupts the protocol.

## Tuning constants

`src/core/work_units.py`:

| Constant | Value | Effect |
|---|---|---|
| `MAX_DAILY_WORK_UNITS` | 20 | Units kept per day, highest score first, after the per-session cap below. Measured peak was 19/day pre-chunking; splitting long sessions into evidence-sized chunks means most busy days now hit this cap. |
| `MAX_SESSION_WORK_UNITS` | 5 | Chunks kept per session per day, before the day cap. Without this, one long session split into many chunks could consume the whole day's cap and crowd out every other session. |
| `SESSION_GAP_THRESHOLD` | 1h | Idle gap between events that starts a new chunk within one session, in `_split_session_events`. |
| `MAX_UNIT_EVIDENCE` | 6000 | Chars of evidence per unit prompt. Also the size threshold `_split_session_events` chunks on, so a chunk's own evidence fits without `WorkUnit.prompt()` truncating it. |
| `MAX_EVENT_CONTENT` | 1600 | Chars per event. |
| `COMMIT_ASSOCIATION_WINDOW` | 4h | How long after a unit ends a commit can still attach to it. |

`session_metadata()` on each driver re-reads the same session files as
`history_since` to collect models and transcript paths (~0.5s for 78 sessions).
It is cursor-free and read-only, like `history_since`.

`normalize_events` dedupes on `(source, session_id, role, content_hash)` with no
date component, so a message repeated within one session is credited to whichever
date iteration reaches first. Comparing two different `--days` values can shift a
few events between dates as a result.

## launchd on macOS

`infrastructure/install_launchd.sh` **generates** both plists from heredocs and
manages exactly two labels: `com.autograph.observer` and `com.autograph.summary`.

Edit the installer, not `~/Library/LaunchAgents/*.plist` — a re-install
overwrites live plists. `uninstall_launchd.sh` also only knows those two labels,
so any other `com.autograph.*` job is a leftover it will not clean up.

launchd runs `/usr/bin/python3` (3.9.6), so keep the code 3.9-compatible. A
`StartCalendarInterval` job missed while the machine is off or asleep fires once
on next wake or boot — not once per missed occurrence.
